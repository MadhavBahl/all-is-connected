Cyclic or acyclic? Can you get back home?

Cyclic

The "Good morning" forward

Sharma Uncle → Mom → Aunty → Neighbour → back to Sharma Uncle. Follow the arrows and end up home: that's a cycle.

Like every 70s film: brothers lost at a fair, reunited in the climax.

Acyclic

The family tree

Grandpa → Dad → you. Follow the arrows as far as you like; you never get back to the start.

Nobody is their own grandfather. Not even in a Bollywood double role.

Connected + no cycles = a tree. Directed + no cycles = a DAG. Both come back later today.

Reel 1 is "2 States": graphs come in a few shapes, and there are two ways to walk them. Start with the most useful shape question: is there a cycle?

A cycle is a path that starts and ends at the same node without reusing an edge. The marigold dot on the left keeps circling, like the forward that never dies. Ask the room: "Who has received their own forward back?"

Why it matters: cycles are why traversals need a "visited" set (or they loop forever), and why topological sort fails (Reel 3). The lost-and-found brothers line is the classic separated-at-the-fair plot of 70s Hindi cinema.

2 States · two ways to walk a graph

Same graph, two personalities

Time BFS & DFS O(V + E)V = nodes, E = edges

BFS · Breadth-First Search

The hostel gossip

Tells everyone one room away first, then everyone two rooms away. Level by level, nobody skipped.

Use it for: fewest hops, shortest path when every edge costs the same, "people you may know".

Uses a queue: first in, first out

DFS · Depth-First Search

The 3 AM YouTube rabbit hole

One video leads to the next, deeper and deeper. At a dead end it does the DDLJ move: "Turn around… turn around." Then it tries the next branch.

Use it for: exploring everything, mazes, cycle detection, topological sort.

Uses a stack (or recursion): last in, first out

Your homework: code both and find A → K on the tree. Hint below ↓

Plot twist: same code. queue.popleft() → BFS. stack.pop() → DFS.

Both run in O(V + E). The only difference is which waiting node you take next: the oldest (queue → BFS) or the newest (stack → DFS). Click once per persona, then once for the homework, then the plot twist; it's the line people remember.

Homework: implement BFS and DFS in any language and print the path A → B → E → K on the 4-level tree from the previous slide. The plot twist is the hint: write one function and only swap popleft() for pop().

"Turn around" is Raj at the end of DDLJ. Turning back from a dead end is called backtracking.

      Dijkstra's algorithm · 1959

      Always finish the nearest place first

      1. Start: source = 0, every other place = ∞. Everything is far away.
      2. Pick the closest unfinished place from a priority queue and lock it in.
      3. Relax its roads: found a shorter way to a neighbour? Write it down.
      4. Repeat until your destination is locked.

      Why it works: with no negative roads, the closest unfinished place can't get any closer later. Locking it in is safe.

      Time Dijkstra O((V + E) log V)V = places, E = roads

      type Graph = Record<string, [string, number][]>;

function dijkstra(graph: Graph, start: string) {
  const dist: Record<string, number> = {};
  for (const node in graph) dist[node] = Infinity;
  dist[start] = 0;
  const pq: [number, string][] = [[0, start]];
  const locked = new Set<string>();

  while (pq.length) {
    pq.sort((a, b) => a[0] - b[0]);  // nearest first
    const [d, u] = pq.shift()!;      // pick nearest
    if (locked.has(u)) continue;     // stale, skip
    locked.add(u);                   // lock it in
    for (const [v, w] of graph[u])   // relax roads
      if (d + w < dist[v]) {
        dist[v] = d + w;
        pq.push([dist[v], v]);
      }
  }
  return dist;
}

      TypeScript. Sorting keeps it short; real code uses a min-heap. Practice: LeetCode 743.

      "Relax" sounds odd; it just means "check if going through this place gives a shorter route, and if yes, update it". A priority queue is a list that always hands you the smallest item first (Python: heapq).

      Point at three lines of code: pq.shift() after the sort (pick the nearest), the stale check with locked, and the relax "if". Everything else is setup.

      TypeScript has no built-in heap, so the sample sorts the queue each round to stay readable. With a real min-heap the running time is O((V + E) log V).

      Dijkstra published it in 1959 and said in a 2001 interview that he designed it in about twenty minutes, sitting at a café terrace, without pen and paper.

      💡 Bonus · explore in your free time

      What's better than Dijkstra? A* is!

      Time Both, worst case O((V + E) log V)V = grid cells, E = moves

      A* = Dijkstra + a sense of direction. Dijkstra spreads like a ripple in every direction. A* adds a guess of the distance left to the goal, so it heads that way first and checks far fewer cells. Same shortest path, less work.

      Ask for a prediction first: "Who wins?" Both find a path of the same length; A* checks about a third as many cells (196 vs 622). On a real map with millions of junctions, that difference is the whole game.

      Keep A* light: this is a teaser, not a lesson. One line is enough: A* scores each place as f = g + h, where g is the distance travelled so far (Dijkstra's part) and h is a guess of what's left (here, Manhattan distance |dx| + |dy| on the grid). If h never overestimates, A* still finds the shortest path. Dijkstra is just A* with h = 0. Tell them to look it up later; it's the algorithm behind game pathfinding and a lot of maps.

      If anyone asks how Google Maps does it at country scale: engines precompute shortcuts once (Contraction Hierarchies, used by open-source engines like OSRM), then each query searches a much smaller graph. Negative weights (cashback, refunds) need Bellman-Ford instead of Dijkstra.

        The story: @sam and @priya both have 3 followers, a tie if you only count followers. But @sam's followers are bots nobody follows, while @priya's are popular students. Everyone starts with 12.5 points.

        The sharing rule (the close-up section): every account takes its points and splits them equally among the accounts it follows. Bot 1 follows only @sam, so all 12.5 goes to @sam. @kabir follows 2 people, so each gets 12.5 ÷ 2 = 6.25.         Then everyone does it at once, round after round. Round 1: @sam jumps to 37.5 thanks to the bots. Round 2: nobody follows the bots, so they received nothing and have nothing left to give; @sam drops to 0. The points end up circulating among the popular students, and @priya settles at 40. A follow is only worth what the follower is worth.

        If someone asks: real Google PageRank adds one tweak. Each round, everyone keeps a small fixed share (15%) no matter what, so nobody drops to exactly 0. That changes the numbers a little, not the ranking. The next slide's live demo uses that version.

          AI agents · a workflow is a graph

          Nodes are steps. Edges are "what next?"

          Example task

          "Find me the cheapest flight to Goa next weekend, under ₹5,000."

            Teal = tool call · Dashed = decision · The loop back is a cycle: retry until the check passes.

            An AI agent is an LLM that can take steps: plan, call tools (search, calculator, a booking API), check its own work and try again. Developers draw these steps as a graph, and popular frameworks such as LangGraph literally make you define nodes and edges.

            Press "Run the agent". Narrate as the dot moves: plan, call the flight-search tool, check the budget, fail, loop back, search again, pass, answer. Callbacks: the loop is the cycle from Reel 1, and the order of steps is the topological thinking from Reel 3. Without a limit on retries, a cycle can run forever, so real agents cap the number of loops.

            Graph neural networks (GNNs)

            Guess what a student likes, from their friends

            A GNN is AI that learns from connections: it looks at a person and at who they're connected to. Used in Google Maps, Pinterest, fraud detection and drug discovery.

            The setup: a college app knows 5 students' hobbies: 🏏 cricket or 🎮 gaming. Kunal, Arjun and Tara never told it (?). Lines = friendships.

            The idea: friends usually like similar things. So each unknown student collects their friends' hobbies and mixes them. This is called message passing.

            Time per round O(V + E)V = students, E = friendships

            A graph neural network learns from connections, not just from each data point on its own. The core move is message passing: every node asks its neighbours "what are you like?", mixes the answers with what it already knows, and updates itself.

            Press "Pass messages". Layer 1: each unknown student mixes in their friends. Layer 2: they now also hear from friends of friends. Kunal ends up about 81% cricket, Tara about 94% gamer, Arjun leans gamer. The demo mixes by simple averaging; a real GNN learns how much weight to give each message, with many numbers per node instead of one.

            Real uses, if asked: Google Maps used GNNs (with DeepMind) to improve arrival-time predictions; Pinterest's PinSage recommends pins; banks spot fraud rings; pharma models molecules as graphs.
